# Architecture audit (before implementation)

- Backend: CommonJS JavaScript, Express 5.2, Mongoose 9.10, Redis 6.2 client; Docker Node 22 Alpine. `npm test` uses Node's test runner and real isolated `mongod`/`redis-server`. No compile step. Existing Docker image starts nodemon; Compose is development only.
- Frontend: Angular 21.2, TypeScript 5.9, Tailwind 4/DaisyUI 5, reactive forms/signals; Angular unit-test builder with Vitest/jsdom. `npm test -- --watch=false`, `npm run build -- --configuration production`. Actual output to verify: `dist/luminabeauty-app/browser`.
- Account identifier: email. Mongo User has COMMON_ROLE/ADMIN_ROLE, state, google, isAuthenticated. Backend registration/login policy is minimum 4 characters, no complexity requirement; frontend registration incorrectly allows 3. bcryptjs default salt cost 10.
- Existing authentication: `/api/auth/login` checks password and immediately returns a 4-hour JWT `{uid}`. Registration navigates to `/auth/twofa`, which calls `/request-code` and `/2fa/verify`. Despite the task's premise, ordinary login does **not** send a code in this checkout. `isAuthenticated` is persistent, not a per-login challenge. JWT middleware checks user existence/state, with no refresh-token store or revocation mechanism. This limitation is not silently described as secure per-login MFA.
- Existing OTP: `crypto.randomInt(10000000,99999999)`, eight numeric digits; purposes `2fa` and `reset`; Redis `${type}:${email}`, TTL 900 seconds. Comparison then DEL is non-atomic; no server attempts/cooldown. Frontend 2FA has a 30-second UI-only resend timer.
- Email: Nodemailer Gmail transport using MAIL_USER/MAIL_PASS; shared LuminaBeauty HTML template, 15-minute guidance, security notice. Sender helper currently swallows transport errors.
- Recovery: existing `/password/verify-reset` consumes code and writes password in one request. `/auth/restore` is a placeholder, login link points to `#`. Extend existing `reset` purpose and helpers, add request/verify/reset stages and opaque Redis-backed authorization.
- API: `/api` prefix, `{ok,msg}`, express-validator validation messages in `{ok:false,msg}`; frontend shared alert components and FormUtils. AuthService converts errors to values; other services parse HTTP errors. Recovery will use typed HTTP errors and existing alerts.
- Styling: white authentication card, indigo controls, gray labels, existing auth layout. No separate auth dark theme. Lazy parent auth routes; restore route will also lazy load.
- Environments: frontend services import both environment files; both currently localhost:8080. Production configuration must replace development imports too. Backend uses MONGODB_CNN, REDIS_URL, SECRETEORPRIVATEKEY, MAIL_USER/PASS, AWS_REGION/AWS_BUCKET_NAME and existing S3 media service.
- Infrastructure: no Jenkinsfile or IaC found. Existing S3 is for product media/logo, not evidence of CloudFront or frontend hosting. No domain/HTTPS configuration found. Preserve Docker; Terraform will reference an existing VPC/subnet/database/Redis, provision EC2 with SSM plus separate static frontend/artifact buckets. No DB/Redis provisioning.
- Branches: both working on develop; main exists and is origin default. Use protected main plus explicit deploy parameter for deployment; feature/PR/develop test and build only.
- Both working trees already contain substantial order/report changes. Preserve them and report final Git state separately from this task's additions. No commits/pushes.
